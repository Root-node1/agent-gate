Executive summary

The backend is a Django 6.1 + DRF 3.18 application with a clean modular structure (backend/apps/). It implements a deterministic policy engine (backend/engine/) as a pure Python package with zero Django dependencies. The backend has comprehensive models, migrations, and admin registration for all core domains. However, critical payment execution and webhook handling are not implemented — PayPal integration is entirely missing.

Critical blocker: The FakeExecutor stub in backend/apps/payments/executors.py simulates payment outcomes but never calls the PayPal REST API. There is no POST /webhooks/paypal/ endpoint and no webhook signature verification.

2. Authentication and authorization

Agent API key authentication (apps/agents/authentication.py)

  • Status: Implemented
  • Mechanism: Authorization: Bearer agk_... → prefix lookup + constant-time SHA-256 hash comparison
  • Features: Suspended agent rejection, revoked key rejection, last_used_at throttling (1-min interval)
  • OpenAPI: AgentKeyScheme extension for drf-spectacular
  • Tests: test_api.py::AuthTests (missing key, wrong key, suspended agent, revoked key)

Dashboard session authentication

  • Status: Implemented (uses DRF SessionAuthentication)
  • Permission Classes: IsApprover (admin/approver), IsDashboardUser (any role), IsOrganizationAdmin (admin only)
  • Scope: All dashboard endpoints filtered by OrgMembership roles
  • Tests: Implicit via approval/audit/policy view tests

CSRF and CORS

  • Status: Partial
  • Dev: Vite proxy (/api and /v1 → localhost:8000) avoids CORS
  • Prod: CSRF_TRUSTED_ORIGINS from env, SECURE_PROXY_SSL_HEADER, SESSION_COOKIE_SECURE, CSRF_COOKIE_SECURE
  • Missing: Explicit CORS headers for non-browser clients (not needed if only dashboard + agent API)
