Executive summary

The frontend is a React 19 + TypeScript + Vite single-page application with a data router (react-router v7). It implements a complete dashboard for managing AI agent spending policies, approvals, transactions, audit logs, and agent settings.

Key finding

The frontend uses an in-memory demo store (frontend/src/demo/store.ts) that replicates the backend rule engine in TypeScript. All dashboard screens consume this mock data instead of calling the actual backend API. The real API client (frontend/src/api/spendRequests.ts) exists but is only used by the Simulator page for agent-key-authenticated spend requests.

Screen-by-screen analysis

1. Landing Page (/)

  • Component: frontend/src/pages/LandingPage.tsx
  • State: COMPLETE
  • Implementation: Static marketing page with hero, feature cards, decision explanations, code sample, CTA to simulator.
  • Data: Hardcoded scenarios (SCENARIOS from landing/content.ts) and rule info (RULE_INFO from demo/rules.ts).
  • Backend integration: None required.
  • Accessibility: Skip link, semantic HTML, ARIA labels on icon-only elements.

2. Dashboard Shell (/app/*)

  • Component: frontend/src/ui/AppLayout.tsx
  • State: COMPLETE
  • Implementation: Sidebar navigation, responsive drawer, user avatar, logout (demo-only), theme tokens.
  • Auth: Uses SessionProvider (frontend/src/session/SessionProvider.tsx) which reads a hardcoded demo user from localStorage or defaults to admin@agentgate.dev. No real session auth against backend.

3. Overview Page (/app/overview)

  • Component: frontend/src/pages/app/OverviewPage.tsx
  • State: MOCKED
  • Data Source: useDemoState() → frontend/src/demo/store.ts → buildSeed() generates 4 agents, 2 weeks of requests, approvals, audit events.
  • Features:
    • Stat cards: total/allowed/denied/pending counts
    • Decisions chart (Recharts-like custom SVG)
    • Recent requests list
    • Budget card (today/month progress bars)
    • Live activity feed (animates new events)
  • Missing: Real API integration, WebSocket/SSE for live updates, date range picker.

4. Approvals Page (/app/approvals)

  • Component: frontend/src/pages/app/ApprovalsPage.tsx
  • State: MOCKED
  • Data Source: Demo store state.approvals filtered by tab (pending/approved/denied/expired).
  • Features:
    • Tabs with counts
    • Oldest-first pending queue
    • Risk badges (high/medium) from riskIndicators()
    • Expiry countdown with urgency styling
    • Links to detail page
  • Missing: Real API (GET /v1/approvals/), pagination, server-side filtering, role-based access (approver/admin only).

5. Approval Detail Page (/app/approvals/:id)

  • Component: frontend/src/pages/app/ApprovalDetailPage.tsx
  • State: MOCKED
  • Data Source: Demo store lookup by ID.
  • Features:
    • Why-it-needs-approval explanations (whySentences())
    • Risk signals (riskIndicators())
    • Rules that fired (ReasonList)
    • Timeline (Timeline component)
    • Agent/policy context with budget meters
    • DecisionPanel: Modal confirm for Approve/Deny → calls decideApproval() in demo store
    • OutcomePanel: Shows decision, approver, note, payment status, PayPal reference
  • Missing: Real API (GET/POST /v1/approvals/{id}/approve|deny), recheck failure handling (409 with rules), loading/error states.

6. Transactions Page (/app/transactions)

  • Component: frontend/src/pages/app/TransactionsPage.tsx
  • State: MOCKED
  • Data Source: Demo store state.requests with client-side filters (filters.ts).
  • Features:
    • Search (merchant/ID), agent filter, decision filter, payment status filter, date range tabs
    • Paginated table (load more)
    • Decision + Payment status badges
    • Links to detail page
  • Missing: Real API (GET /v1/spend-requests/ with query params), server-side pagination, cursor-based pagination.

7. Transaction Detail Page (/app/transactions/:id)

  • Component: frontend/src/pages/app/TransactionDetailPage.tsx
  • State: MOCKED
  • Features: Full request details, decision reasons, payment status, PayPal reference, timeline.
  • Missing: Real API integration.

8. Agents Page (/app/agents)

  • Component: frontend/src/pages/app/AgentsPage.tsx

  • Data Source: Demo store state.agents with computed activity stats.

9. Agent Detail Page (/app/agents/:id)

  • Component: frontend/src/pages/app/AgentDetailPage.tsx
  • State: MOCKED
  • Features: Agent info, key reveal modal (shows full key once), revoke/rotate buttons → demo store actions.
  • Missing: Real API endpoints for key management.

10. Policies Page (/app/policies)

  • Component: frontend/src/pages/app/PoliciesPage.tsx
  • State: MOCKED
  • Data Source: Demo store state.policies with budgetUsage() selector.
  • Features: Table with per-payment limits, daily/monthly budget usage bars, merchant allow/block counts, links to edit.
  • Missing: Real API (GET /v1/policies/ exists but returns different shape — backend includes merchant_rules array, frontend expects allowed_merchants/blocked_merchants arrays).

11. Policy Edit Page (/app/policies/:id)

  • Component: frontend/src/pages/app/PolicyEditPage.tsx
  • State: MOCKED
  • Features: Form with validation (validatePolicy()), merchant list editors (allow/block), save → updatePolicy() in demo store.
  • Missing: Real API (PATCH /v1/policies/{id}/ — backend endpoint does not exist).

12. Audit Log Page (/app/audit)

  • Component: frontend/src/pages/app/AuditLogPage.tsx
  • State: MOCKED
  • Data Source: Demo store state.events transformed by buildRows() (auditData.ts).
  • Features:
    • Filters: search, event type (grouped), agent, actor, date range
    • Server-side pagination simulation (client-side)
    • CSV export (downloadCsv())
    • Event drawer with full payload
    • Actor labels, decision badges, request links
  • Missing: Real API (GET /v1/audit/ exists with different params), GET /v1/audit/verify/ (admin only).

13. Settings Page (/app/settings)

  • Component: frontend/src/pages/app/SettingsPage.tsx
  • State: MOCKED
  • Sections (from settingsData.ts):
    • Workspace: name, timezone, demo reset button
    • Team: member list with roles (admin/approver/viewer)
    • Developers: API keys (placeholder), webhooks (placeholder)
    • PayPal: sandbox credentials form (placeholder)
  • Missing: All real API integrations. Backend has no workspace/team/settings endpoints.

14. Simulate Page (/app/simulate) — Only Real API Consumer

  • Component: frontend/src/pages/app/SimulatePage.tsx
  • State: PARTIAL
  • Data Source: Real backend API via submitSpendRequest() from frontend/src/api/spendRequests.ts
  • Features:
    • Agent key input (stored in localStorage)
    • Scenario presets (Allowed, Needs Approval, Denied)
    • Custom request form with validation
    • Shows raw JSON response
    • Error handling for 400/401/409
  • Backend Integration: POST /v1/spend-requests/ with Authorization: Bearer <key> and Idempotency-Key.
  • Gaps:
    • No idempotency key management (generates random each submit)
    • No polling for approval→payment status
    • No webhook simulation
    • Hardcoded to http://localhost:8000 (via Vite proxy)

15. Live Pages (/live/*)

  • Components: TesterPage, RequestsPage, RequestDetailPage
  • State: MOCKED / DISCONNECTED
  • Purpose: Alternative testing UI with agent key authentication.
  • Data: Mix of demo store and local state.
  • Missing: Real backend integration for live request history.

Missing functionality (frontend)

  1. Real dashboard authentication flow — Session login, protected routes, role-based redirects.
  2. API client layer for all dashboard endpoints — Approvals, policies, audit, agents, settings.
  3. Error boundaries — No React error boundaries for graceful degradation.
  4. Loading states — Only simulated via useSimulatedLoad() (artificial delay).
  5. Empty states — Implemented via EmptyState component (good).
  6. Real-time updates — No WebSocket/SSE for live feed, approval queue updates.
  7. Pagination — Client-side only; backend uses limit/offset (DashboardPagination).
  8. Keyboard navigation — Tables use row-link but not all interactive elements are keyboard-accessible.
  9. Internationalization — Hardcoded English only.

Recommendations

Before backend deployment (critical)

  1. Implement dashboard authentication flow — Session login, protected routes, role-based redirects.
  2. Build API client layer for all dashboard endpoints (approvals, policies, audit, transactions).
  3. Align rule codes between frontend demo (demo/rules.ts) and backend (engine/rules.py).
  4. Implement missing backend endpoints: Agent CRUD, Policy update, Transaction list (dashboard-scoped), Settings.

After staging deployment

  1. Real-time updates — WebSocket/SSE for approval queue, activity feed.
  2. Idempotency key management in Simulate/Live pages.
  3. Payment status polling after approval.
  4. CSV export streaming for large audit logs.

Optional for MVP

  1. Internationalization framework.
  2. Advanced filtering (saved filters, column visibility).
  3. Keyboard shortcuts for power users.
  4. Dark mode (CSS variables exist in tokens.css).
