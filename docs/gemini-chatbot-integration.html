Executive summary

The existing frontend has no chatbot component. There is no backend chatbot endpoint, no Gemini SDK usage, and no AI model serving code anywhere in the repository. The only "live" UI elements are the activity feed on the Overview page (which animates demo-store events) and the Simulate page (which submits real spend requests via the agent API).

Critical finding

The Gemini chatbot does not exist yet. It must be built from scratch as a backend-proxied, read-only advisory assistant. The Gemini API key must never leave the server.

Missing integration work

The chatbot requires work in two layers — backend proxy and frontend UI.

Backend (new apps/chatbot/)

  • A new Django app apps/chatbot/ with:
    • A view POST /v1/chat/ authenticated via SessionAuthentication (dashboard users only)
    • A service layer that constructs a system prompt, appends conversation context, calls the Gemini API, and returns a text response
    • Per-user conversation memory (short window, e.g., last 10 messages) stored in the session or a lightweight in-memory store
  • Registration in INSTALLED_APPS in config/settings/base.py
  • Routing in config/urls.py
  • Google Gemini SDK added to requirements.txt

Frontend (new chat component)

  • A new ChatWindow component (frontend/src/chat/ChatWindow.tsx) with:
    • Message list (assistant + user bubbles)
    • Input field with send button
    • Typing indicator and error toast
  • A new API client frontend/src/api/chatbot.ts calling POST /v1/chat/
  • A new route /app/chat in frontend/src/App.tsx
  • Integration into the AppLayout.tsx sidebar

Gemini API  (google-genai Python SDK)
Key principle: The Gemini API key is stored in backend/.env as GEMINI_API_KEY and is read by the Django backend at runtime. The frontend never receives the key, never sets it as a Vite environment variable, and never has it in the bundle. The vite.config.ts proxy already routes /v1/* to the Django backend, so no cross-origin exception is needed.

Recommended Gemini SDK and backend service structure

SDK choice

Use the official Google GenAI Python SDK (google-genai), which is the successor to google-generativeai. It is the SDK recommended by Google AI Studio and provides structured response handling, retry with exponential backoff, and built-in safety filtering.

System prompt and read-only guardrails

The system prompt must explicitly instruct the model to act as an advisory, read-only assistant. The following guardrails are non-negotiable:

Prohibited actions — the chatbot must never:

  • Execute PayPal transactions (no call to PaymentExecutor or PayPal API)
  • Approve or deny spend requests (no call to apps/approvals/services.decide())
  • Modify policies (no call to policy CRUD endpoints)
  • Create or revoke API keys (no call to agent key management endpoints)
  • Bypass the deterministic policy engine (backend/engine/rules.py)
  • Expose sensitive audit information or secrets (no raw AuditEvent.payload, no amounts, no payee details unless sanitized)

The system prompt should be embedded in prompts.py and include:


You are "AgentGate Assistant", an advisory chatbot for the AgentGate
spending firewall dashboard. Your role is to help authenticated dashboard
users understand spending policies, request outcomes, and audit events.

You are strictly read-only. You must NEVER:
- Approve or deny spend requests.
- Execute payments through PayPal.
- Modify policies, budgets, or merchant rules.
- Create, rotate, or revoke API keys.
- Bypass or override the deterministic rule engine.
- Reveal raw audit-chain hashes, internal IDs, or secret material.

When a user asks about a specific spend request, provide a summary of
the decision, the matched rule codes, and whether it was allowed, denied,
or needs approval. Never output raw JSON payloads or database IDs.

If a user asks you to perform a prohibited action, respond with:
"I can only provide information — I cannot [action]. Please use
the dashboard controls directly."

Never add GEMINI_API_KEY to frontend/.env, vite.config.ts, or any file under frontend/src/. Vite's build system inlines import.meta.env.VITE_* variables into the client bundle — the key would be visible in browser dev tools. The proxy at vite.config.ts:8-11 already routes /v1/* to the Django backend, so the frontend needs only: 

// frontend/src/api/chatbot.ts
async function chat(message: string) {
  const res = await fetch("/v1/chat/", {
    method: "POST",
    credentials: "include",
    headers: {
      "Content-Type": "application/json",
      "X-CSRFToken": getCsrfToken(),
    },
    body: JSON.stringify({ message }),
  });
  return res.json();
}

Privacy and prompt-injection safeguards

Prompt-injection safeguards

  • Input length cap: Reject messages longer than 2,000 characters before sending to Gemini.
  • Pre-screening: Run the user message through the deterministic injection screening (backend/engine/screening/patterns.py, rule R14_INJECTION_PATTERN) before forwarding to Gemini. If a match is found, return a canned advisory response instead of calling the API.
  • No tool calling: The Gemini request must use tools=[] (no function calling, no code execution). The model cannot call external functions.
  • No retrieval of raw audit data: The chatbot must never query AuditEvent directly with raw payloads. Only sanitized, human-readable summaries are provided.

Privacy considerations

  • Data retention: Conversation history is stored in-memory only (or in the Django session store). It is not persisted to the database unless the team explicitly adds a Conversation model in a follow-up.
  • No PII in logs: The backend must never log user messages to structured logs. Only log request metadata (user ID, timestamps, token counts, errors).
  • PII redaction in responses: If the model summarizes a spend request, it must not include payee email addresses, PayPal references, or raw merchant URLs — only merchant names and outcome codes.
  • Cost attribution: Log usage_metadata (prompt + output tokens) per user for billing/debugging purposes.

Usage limits and cost controls

Model choice for cost control

Use gemini-2.5-flash by default, not gemini-2.5-pro. Flash is 3×–10× cheaper and sufficient for advisory Q&A. Allow GEMINI_MODEL to be configured per environment.

Token limits

ParameterDefaultRationale
max_output_tokens1024Prevents runaway responses; advisory answers are short.
temperature0.2Low temperature for deterministic, consistent answers.
History window10 messagesKeeps context small and costs predictable.
Input length cap2,000 charsPrevents oversized prompts before they reach the API.

Cost monitoring recommendations

  • Log token usage (prompt_token_count, candidates_token_count) per POST /v1/chat/ request in structured JSON logs.
  • Set Google Cloud budget alerts on the AI Studio project (e.g., $10/month soft limit).
  • Consider per-user daily quotas in the Django throttle to prevent abuse.
  • Review GEMINI_MODEL quarterly — downgrade from Pro to Flash when cost exceeds budget.
